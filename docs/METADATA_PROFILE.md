# Museum of One metadata application profile 3.0

This local application profile defines the identities, evidence boundaries and validation rules used by the archive and its discovery exports. It supports reuse without claiming external standards certification or factual infallibility. `data/metadata-profile.json` publishes the core JSON Schema and local projection rules; `scripts/metadata_profile.py` applies the corresponding checks plus date, scope, graph and citation constraints.

## Stable identities

| Thing described | Identifier |
| --- | --- |
| Local work | `/items/{id}.html#work` |
| Selected deposited edition | Version-specific `https://doi.org/{doi}` |
| Repository version family | Concept DOI, when supplied |
| Local catalogue description | `/items/{id}.html#catalogue-record` |
| Catalogue webpage | `/items/{id}.html#webpage` |
| Contextual person, organisation, artwork or exhibition | `/entities/{slug}.html#entity` |
| Analytic component | `/parts/{parent}-{component}.html#component` |
| Original repository file | Existing item file node plus its unchanged repository content URL |
| Verified reading copy | Its local PDF URL and recorded digest |

The shared `identities` module constructs item, work, catalogue and entity URIs. The page route remains stable; a thing and the page describing it are distinct. A renamed label must not silently change a previously issued identifier. Retired or merged records require a documented mapping and a retained landing/tombstone page; identifiers are never recycled.

ORCID and other external authority identifiers remain attributed identifiers. Their presence alone does not assert independently verified equivalence, affiliation or endorsement. Person and publisher nodes use the local contextual identity where a maintained relationship exists. A work-level identity is distinct from a repository version-family DOI: neither a new deposit version nor a changed catalogue description establishes a new intellectual work.

## Source scope controls projection

The reviewed institutional page metadata supplies `linked_zenodo_dois`. A selected edition DOI in that list permits `exact_edition`; a matching concept DOI permits `version_family`; otherwise the corroborated connection remains `work`. The institution's graph node points to that scoped target. The classification is recomputed from the evidence rather than trusted as an editable cached label.

Existing book ISBNs remain visible as source-reported title-level identifiers. An ISBN travels as an edition `isbn`, citation ISBN or generic edition identifier only when `isbn_evidence` explicitly records `scope: edition_format`, `status: source_verified` or `registry_verified`, `source_url` and `reviewed`. This export requirement does not discard a printed/source identifier. It preserves the unresolved edition/format allocation in the qualified work and catalogue record. Identifier checksum validity is separate from assignment and scope.

Citation title comes from `source_title`; a local display title is a fallback only when no source title exists. CSL-JSON, BibTeX, RIS, visible citations and applicable Scholar tags are generated by the same citation model. Dataset citations remain available without presenting a dataset page as a scholarly article.

## Typed, evidenced relationships

The versioned local relation register covers authorship, publishing, discussed artists/artworks/exhibitions/scholars/curators, scholarly correspondence, artwork creator attribution, scoped curatorial discussion and institutional description. Each relation specifies its domain/range and inverse label. It does not imply coauthorship, collaboration or endorsement from a discussion relationship.

`typed_relationship_assertions(record, origin)` and `typed_entity_relationship_assertions(entities, origin)` emit:

- A deterministic assertion identifier derived from subject, predicate, object and source.
- Subject, registered predicate and object URIs.
- Evidence scope and a declared evidence status.
- Source URL and locator. Current webpage evidence defaults to page precision; that is not a passage verification.
- Review date and reviewer when recorded, with explicit unknowns otherwise.
- The source-qualified descriptive note.

A different reviewer/date does not silently create a different subject–predicate–object assertion. New evidence sources produce their own assertion IDs. Locators may be added only after checking the source; `pdf_page` locators must fall within the verified reading-copy extent. No source review date is borrowed from a different source URL. Unknown historical review dates and reviewers remain unknown.

Item JSON-LD expresses contextual relations as RDF statements alongside their readable descriptions and provenance. The complete typed assertion export retains qualification that simplified search cards cannot express. Original repository snapshots and PDF bytes are never rewritten by projection.

## Validation and quality dimensions

Validation has separate responsibilities:

1. **Source/profile checks:** required record fields, supported resource types, ID/date/URI syntax, cardinality, unique accessions and DOIs, source-scope consistency, relation vocabulary/type constraints and unchanged derived assertions.
2. **Whole-graph checks:** references across item, component, vocabulary and authority graphs; registered contextual entity identities; undeclared local nodes and incompatible entity types. A syntactically valid JSON document alone does not pass this check.
3. **Export agreement:** on-disk CSL-JSON, BibTeX and RIS match the shared model; applicable HTML Scholar tags agree; JSON-LD edition title/date, ISBN scope and institutional targets agree with the same sources.
4. **Discovery evaluation:** retrieval quality, page arrival, mobile/keyboard use and source-failure behaviour are separate from metadata validity.
5. **External verification:** registry assignment, current link availability and actual search-engine inclusion require separate dated observations.

The quality report supplies counts and explicit unresolved lists: institutional match scopes, relationships with sources, review dates, named reviewers and passage locators; unresolved title-level ISBN format allocation; unknown local creation dates; executed and unexecuted checks. It has no synthetic completeness percentage. An absent optional field is not an invitation to invent a fact.

## Build integration

After normal source enrichment, entity/component/vocabulary/PIRR and history attachment, call `prepare_metadata_records(records, origin)`. This returns copies with profile identifiers, typed assertions and scoped identities. Explicit later events from `data/description-events.json` are added only to their listed record IDs, idempotently. Their dates describe local metadata implementation; no publication, original creation or source-review date is changed.

Gather all item graphs, `component_schema(...)` graphs, `vocabulary_graph(...)` and `entity_graph(...)`. Pass them to `build_quality_report(records, graphs, origin=origin, entity_records=entities)` and `require_valid_report(report)` before writing the release. `combine_graphs(graphs)` creates a deterministic combined graph while retaining namespace contexts and all nonduplicate statements.

After writing output, run `build_quality_report` again with `output_dir=dist` to validate actual exports, then require a passing report. Standard citation filenames are `{record_id}.csl.json`, `{record_id}.bib` and `{record_id}.ris` under `metadata/`. Publish the profile, relation register, assertion dataset, combined graph and quality report from this same generation.

Changing the source schema, identity policy or interpretation of a predicate requires a profile version change and explicit migration notes. Evidence repairs may update an existing assertion without changing its identity; removal/withdrawal must remain in the local description history rather than silently erasing issued identifiers.
